# 复制给 Agent：安装、使用或排查 AgentNotify

请根据我当前明确提出的任务，处理这份 AgentNotify Windows 开发包。先从独立说明 ZIP 解压目录读取 START_HERE.md、MIGRATION.md、SIGNING.md ；如果我另附脱敏协助包，再按问题读取它，首次安装不要求携带源机器的包；没有本机文件或运行权限时说明能力限制，并继续分析可读材料，不假装已安装。

首次安装按邮箱设置、选择客户端、接入、预览测试的顺序协助。总览的“新电脑使用提示词”可独立复制；排障协助包仅按需生成，默认位于程序旁 AgentNotify-assistance 子目录，以界面返回的实际路径为准；生成失败不声称文件已导出。全新且未配置的实例可以选择通过安全校验的新数据目录，已有安装不隐式迁移。保存成功会应用后台配置；客户端信任和重新加载仍按对应接入渠道处理，不混同为保存成功。检测候选、已有登记、历史入站、SMTP 接受与当前真实任务收件分别报告，历史记录不证明当前客户端已经加载。

先探测当前 Windows/架构、实际包位置、WebView2 Runtime、运行用户、已安装 AgentNotify 的版本/构建标识和数据目录。日常入口是 AgentNotify.exe 或安装后的桌面快捷方式。GUI、CLI、后台由同一运行文件按参数分派，不依赖用户启动脚本。运行端无需 Python、Node、Rust 或 PowerShell 7。当前包未签名，核对来源和哈希，不修改系统安全策略、不把哈希冒充发布者签名。

对我的安装/修复授权内必要且可逆的工作自主推进：保留既有配置，先只读检查再预演、备份和按基线应用；复用同一安装实例，所有入口带同一数据目录。通过当前版本正式命令核对后台状态、通知开关、免打扰和工具接入。只合并 AgentNotify 自有 Hook，保留其他客户端配置。未知客户端版本或接口不猜测支持；客户端信任由我确认，不伪造信任、不自动重启 AI 客户端。

若我的目标是 A 机器迁往 B 机器，请严格按 MIGRATION.md：整理允许携带的非秘密通知偏好，在目标重建安装、路径、实例绑定和凭据引用。不要复制 host.json、系统凭据、正文密钥、历史或待发队列、计划任务和客户端信任。目标通知先关闭，确认源机器停发后才启用目标；无源机访问能力时明确交接步骤。当前没有一键跨机导出/导入命令，不要编造。

若我要求卸载，请使用诊断页的两阶段卸载流程：先预览真实清理/保留范围和阻塞项，再由我最终确认。默认 `keep_settings` 只保留邮箱、通知偏好及相应凭据；通知历史、待发队列、旧绑定和 observer 状态不保留，重装建立新基线，不补发旧通知。`remove_settings` 同时清除归属明确的本工具配置与凭据，不等于递归删除数据目录。未知文件、备份或无法确认归属的内容保留并在计划披露；用户修改过的 Hook 冲突、在途投递等应阻止执行，不通过删记录绕过。只清理 AgentNotify 自有条目，保留其他工具及用户配置。

卸载返回 `helper_started` 仅表示清理程序启动，不能报告卸载完成。设置窗口退出后，以返回的报告路径读取最终 `completed` 或 `incomplete`；失败报告需据实说明保留项与后续动作。没有明确执行授权只做预览，不因排查故障而自动卸载；不要将后台服务注册移除冒充完整卸载。

邮箱授权码只由我在本机设置窗口私密输入。你不读取、输出、上传或写入聊天/命令参数。除非我另行明确要求测试邮件，不额外发信。区分配置回读、后台运行、真实客户端事件、SMTP 接受和实际收件。

维护中断时按现有 update-journal.json 记录核对阶段，不删除 maintenance 文件。恢复消费后不能回滚旧数据快照；只使用本版本实际支持的恢复命令。没有正式发布签名时，不生成开发密钥冒充可信更新。单 EXE 安装返回 unified_signed_update_pending 时，表示尚不支持旧三文件签名更新流程，不应绕过校验。升级改用来源已确认的新版 AgentNotify.exe，在授权内按当前实际接口受控操作，先保全现场和回退点，保持设置、凭据与 Hook；执行替换前停止自有 GUI 与后台，由外部新版 EXE 或 Agent 操作；当前没有内置静默替换运行中自身的能力，不能声称自动更新。

最后简明报告实际修改、验证层级、安装与数据位置、可回退点、我仍需私密输入或审核的动作。Windows 证据不代表 macOS/Linux 已实测。

运行文件为独立 AgentNotify.exe，说明 ZIP 不含程序或脚本。通过实际 CLI 帮助确认命令，使用探测到的绝对路径，不依赖当前工作目录。优先发现并安全验证已有用户 profile 安装，多个安装时明确选择；所有入口保持同一数据目录，不放宽 ACL。保留已有稳定 launcher 兼容入口、安装记录和客户端 Hook 路径；一个交付 EXE 不等于可以删除安装后的数据/版本文件。

若正常 Codex Hook 未产生可用完成通知，按我的授权为具体实例检查只读备用接入：适配器以只读方式读取 thread_history_1.sqlite 与 state_5.sqlite 的完成元数据，并仅按正文开关有界读取匹配轮次内容，后台每 2 秒扫描；核心只收中立事件。先核对客户端版本/数据库/schema 与实际命令，不臆造启用接口，不修改 Codex 数据库。初始化成功才把该实例完成类通知交由 observer 独占，保留已信任 Hook 命令及生命周期；不能宣称任意双源 ID 已统一。检查首次基线排除已完成历史并跟踪进行中任务、ACK 后游标推进与稳定入站 ID 去重。thread_spawn 子代理不产生邮件，主会话最终回复正常通知，guardian 仅按结构来源排除，未知来源不靠 JSON 形状过滤。按用户正文开关有界读取新匹配轮次，缺正文不编造。诊断只报告兼容/初始化/游标和接收状态的必要脱敏证据，不导出数据库或正文；degraded 需报告原因与下一步，不谎称健康，也不为排查主动补发历史。

备用接入首次启用有前置条件：该实例不能已有 Hook 入站记录，且 AgentNotify 整个 spool 必须为空。已有 Hook 历史的实例暂不支持在线切换，应明确拒绝，不清除记录绕过限制，也不猜测跨通道子代理 ID 去重。首次基线与启用使用共享仲裁锁，避免与 Hook 并发入队。已经启用的 observer 重启后保持来源，不重建历史补发；故障显示降级，不自动回退 Hook 完成通知。先验证本机前置条件，不把其他机器或一次零记录检查当作永久保证。

首次接入按兼容清单核对客户端；已启用的观察绑定按原实例、原数据目录和实际观察契约验证，客户端版本、EXE 路径或无关 Hook 的变化无需重绑。确认实例已正式登记后，实际启用接口为 `AgentNotify.exe --data-dir <root> observer enable codex --instance-id <已登记UUID>`，将占位符替换为已核实本机值，不猜实例 ID。旧线程创建版本不用于排除当前版本中的续轮；正文按同 session/turn 匹配，找不到保持空。扫描上限为 10 万条 turn 元数据，超过上限显示 degraded；每批最多处理 32 个新事件，不能把扫描批次当作额外完成任务。遇到不兼容的结构或完成记录时按诊断处理，不修改数据库格式来绕过限制。

兼容限制：不支持启用观察接入后从外部导入或替换 Codex 历史数据库；数据库时间精度为秒，无法可靠区分同秒导入的历史与新完成任务。正常实时任务按首次基线、当时进行中任务和新任务标识处理，不能为过滤导入历史而丢弃同秒完成任务。来源过滤排除结构化 guardian 及精确 originator 为 `respire-memory-worker` 的后台处理（不区分成功或失败）。来源判断不得依据 JSON 形状或讨论关键词；主会话普通 JSON 和前台讨论按最终回复规则处理，子代理不通知。尚无真实 Respire 持久记录正例验证，不承诺识别未携带该来源标识的后台任务。

同一 AgentNotify 数据目录中，同一个规范化 CODEX_HOME 只能登记一个 observer；程序通过全局启用锁和登记记录拒绝第二实例，不能为同一来源重复创建观察器。

正文排查以 thread_history 的精确 thread/turn/first_user_item_id/final_agent_item_id 投影为依据，仅按相应正文开关读取首条用户提问和最终回答；缺失明确“未取得”，16 KiB 截断需标注。项目名优先读取 Codex 桌面 globalstate 的 thread-project-assignments[threadId] 对应 local-projects[id].name，再依次使用桌面 electron-workspace-root-labels、数据库项目映射和目录名兜底；路径匹配需正确处理 Windows 扩展路径前缀，不硬编码具体项目名称。会话使用主会话真实标题，附件封套和内部 agent 昵称不能替代。Codex 分支主题严格使用“Codex 通知：项目｜会话｜本轮处理结束”，全角｜两侧无空格；正文沿用事件、项目、会话、时间（yyyy-MM-dd HH:mm:ss，无偏移）、“本轮提问”“回答”，结尾为“请回到 Codex 查看结果或处理待办。”。不额外改写样式，单事件不显示“聚合 1”；此格式要求仅适用于 Codex 分支。

Respire 识别使用精确 originator `respire-memory-worker`，该来源所有处理结果均不发邮件，不依赖 JSON 形状或关键词；前台讨论 Respire、普通 JSON 的主会话最终回复仍可通知；子代理和内部阶段不通知。目前没有真实 Respire 持久记录正例，不将历史邮件截图或隔离分类检查说成真实来源识别全覆盖。排查先核对来源证据，不为补齐正文更改用户已开启的设置，也不导出实际问答。

若用户仅要真正阻塞且需要输入/批准时通知，当前独立后台没有已验证的原桌面宿主 pending 信号接入。alpha 协议定义的等待状态、ServerRequest/Resolved 或 permissionRequest 类型不代表现有只读持久库可获取状态或 Hook 已实际投递。不要以 completed/inProgress、超时或猜测代替，不使用会话内 wait_threads 冒充外部订阅。按用户授权暂停自动通知并保留其他设置，明确目标尚未实现；不要擅自创建自动化、桥接聊天或重启宿主来声称支持。

当前默认工作目标是主会话最终回复正常通知，子代理、内部阶段和 Respire 不通知；不能因阻塞提醒尚未接入而把全部通知关闭视为完成。恢复通知时保留已有设置和 observer 基线，历史 suppressed 不补发；阻塞提醒继续标为能力待接入。

邮件问答的 HTML 部分采用安全 Markdown 解析，保留纯文本 fallback 和原外层样式；表格边框、代码灰底仅改变展示，不改变原通知事件和读取范围。排查渲染时不读取或导出真实正文，使用脱敏或合成片段。远程图片禁用、不安全链接禁用，本地文件路径按文字展示；不要把原始 HTML 直接注入邮件。具体实际客户端视觉仍需独立确认，不为展示排查擅自发测试邮件。
