# AgentNotify Windows：从这里开始

日常只需一个 `AgentNotify.exe`。双击打开设置；同一用户、同一数据目录重复打开时唤起已有窗口，设置界面与托盘保持单实例。说明 ZIP 可另外解压查看，不是程序运行依赖。当前为未签名开发构建，SHA256 仅用于文件比对，不证明发布者身份。

1. 将来源已确认的 `AgentNotify.exe` 放到固定位置后打开。已有安装会先按安全检查发现并复用；数据位置可在界面核对。全新且尚未配置的实例可在总览选择自定义安全数据目录；已有安装不隐式迁移。不要自行移动已安装目录或改客户端命令。
2. 如果缺少 WebView2 Runtime，安装微软官方 Evergreen x64 Runtime。离线机器准备微软官方 Standalone Installer。无需安装 Python、Node、Rust 或 PowerShell 7。
3. 在邮箱页填写发件邮箱、授权码和收件邮箱。授权码只在本机私密输入，由系统凭据库保存；不交给 Agent。保存设置不发邮件。
4. 在工具接入页选择检测到的客户端候选，核对版本后准备并应用接入方案；需要时安装本机后台。可逐项接入多个工具；手动路径与版本放在高级设置中。受支持的 Codex 使用本机只读观察接入，Claude Code 使用客户端 Hook。客户端信任或重新加载仍按检测结果由你处理，未知版本不猜测支持。WorkBuddy 仍待研究。
5. 按需设置通知模式、空闲秒数、免打扰和正文开关。缺乏可靠开始信号时，“长时间未结束”提醒保持关闭，可保留阈值。

关闭窗口会收进托盘；“退出程序”只退出设置界面与托盘，独立后台继续按原设置工作。要停用通知，单独关闭“启用通知”。一个 EXE 可启动不同职责的进程；不等于没有配置、队列或安装记录。

如要验证收件，请先预览测试邮件，再明确点击发送。配置保存、后台运行、真实客户端事件、SMTP 接受与实际收件是不同验证层级。正常会话未通知时请通过诊断提供脱敏信息，不把曾收到测试邮件当作接入完成。

新电脑首次使用按“邮箱→选择工具→接入→预览测试邮件”完成，无需迁移协助包。总览可独立复制“新电脑使用提示词”交给 Agent；遇到接入故障才按需生成排障包，生成后显示实际保存位置。

规则和邮箱页的保存栏会提示未保存修改；切页、关闭窗口或退出界面时可选择保存、放弃或继续编辑。保存失败保留草稿。保存成功后后台使用新设置，不需要为保存重启客户端；客户端 Hook 信任与加载是独立步骤。

只有确需从另一台电脑保留偏好时，才阅读说明包的 `MIGRATION.md`，或在诊断中按需生成迁移协助提示词。仅迁可携带偏好；目标重新建立凭据和本机绑定，先停源端再启目标，避免重复发送。

在“诊断 → 卸载 AgentNotify”选择方式，再预览清理范围，最后确认卸载。默认仅保留邮箱、通知偏好与相应授权凭据，不保留通知历史、待发队列和旧接入状态；重新安装后重新接入，不补发旧通知。也可选择清除本工具配置与凭据。程序只清理可确认归属的已知文件和接入项，未知文件或备份保留并在预览中披露；接入冲突、正在投递等阻塞必须先解决，不会通过删除其他工具配置绕过。

确认后设置窗口退出，由独立清理程序处理。“清理程序已启动”不等于卸载完成，最终以显示的报告路径中 `completed`（完成）或 `incomplete`（未完成）结果为准；未完成时按报告处理，不手动清空目录。卸载不会卸载其他客户端。正式签名更新仍未开放，不直接覆盖安装记录指向的程序。

说明包还包含使用、签名、手工验收说明、许可证及构建/哈希信息。程序不需要 VBS、CMD 或 PS 启动脚本；Windows 内部后台管理仍使用系统 PowerShell。macOS/Linux 原生支持及实机验证仍待办。

## Codex 备用接入

当正常任务结束未能通过客户端 Hook 到达时，可让 Agent 为指定 Codex 实例核对兼容性并启用本地只读观察接入。当前仅支持已绑定的 `0.166.0-alpha.5.1` 版本，其他版本不能直接套用。后台约每 2 秒检查一次；只有初始化成功后，该实例的完成类通知才改由观察接入独占，已有 Hook 命令和信任保持不变，生命周期仍保留。不会同时用两路完成通知冒险重复发信。

首次建立基线不补发已经完成的历史任务，但会跟踪当时仍进行中的任务。主会话最终回复可通知；子代理、内部阶段和 Respire 处理不通知，不会仅因主会话回答是 JSON 就过滤。正文遵循你的开关，只读取新匹配轮次，缺失不补造。版本或数据库格式不兼容时会显示降级，需要排查，不能视为已正常接入。邮件仍遵守免打扰、空闲条件和现有通知规则；观察到任务结束不等于邮件已送达。

当前首次启用还要求该实例没有既有 Hook 入站记录，且 AgentNotify 整个离线 spool 必须为空；有 Hook 历史的实例暂不支持在线切换，会明确拒绝。已启用后重启会保持观察接入，不重新补发历史；出现故障会提示降级，不自动退回 Hook 完成通知，避免来源切换造成重复。不要自行清空队列或历史绕过限制。

兼容限制：不支持启用观察接入后从外部导入或替换 Codex 历史数据库；数据库时间精度为秒，无法可靠区分同秒导入的历史与新完成任务。正常实时任务按首次基线、当时进行中任务和新任务标识处理，不能为过滤导入历史而丢弃同秒完成任务。来源过滤排除结构化 guardian 及精确 originator 为 `respire-memory-worker` 的后台处理（不区分成功或失败）。不以 JSON 形状或讨论关键词识别 Respire；主会话普通 JSON 与前台讨论仍按最终回复规则处理，子代理不通知。尚无真实 Respire 持久记录正例验证，不承诺识别未携带该来源标识的后台任务。

Codex 邮件沿用既有通知格式，主题为“Codex 通知：项目｜会话｜本轮处理结束”（全角分隔符、两侧无空格）；正文依次显示事件、项目、会话、时间、“本轮提问”“回答”和回到 Codex 的提示。时间格式为 yyyy-MM-dd HH:mm:ss，不增加 UTC 偏移；单条事件不显示“聚合 1”。提问和回答分别遵循你的正文开关，按同一线程和轮次读取；未取得时明确提示，不拿其他轮次代替。正文达到 16 KiB 上限时会标明截断。项目优先使用 Codex 桌面为当前会话指定的项目显示名，再使用工作目录标签、数据库映射和目录名兜底；会话使用主会话真实标题；附件封套和内部代理昵称不作为主会话标题。历史已抑制通知不会补发。

## 仅在需要用户介入时通知的能力边界

当前尚未接入可供独立后台可靠使用的“等待用户输入/批准”信号，不能把完成事件、进行中状态或长时间无输出当作阻塞。如果只需要此类提醒，应关闭自动通知；不要将关闭完成通知描述为“仅阻塞模式已启用”。协议定义存在相关状态不等于当前桌面宿主已向本软件投递事件。

在“通知记录”点击“查看详情”，可查看已有的项目、会话、来源、发生/接收时间、投递状态与次数、接收规则和诊断信息。未记录的原因不会补造；终态正文按隐私规则清理，详情不恢复或延长问答留存。

邮件中的问答支持基本 Markdown 展示，例如强调、表格和代码块；表格使用边框，代码使用灰底，同时保留纯文本版本供不支持 HTML 的邮件客户端使用。远程图片不加载，不安全链接不生成，本地文件路径保留为文字。不同邮件客户端的显示效果可能不同。

卸载验证范围：当前完成实现与隔离安全检查，完整 Windows 卸载及重新安装尚未实机验证。未知文件、备份和最初下载的程序文件会保留；仅在归属核对通过时自动清理当前用户桌面上本工具的精确快捷方式。不要据此手动删除其他文件。
