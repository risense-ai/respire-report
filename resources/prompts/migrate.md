场景：AgentNotify 从 A 机器迁移到 B 机器（新环境）。这是 Agent 协助迁移，不代表软件已有一键导出、导入或跨机器自动控制能力；仅操作当前用户明确授权且你能够访问的机器。先判断当前是源机器还是目标机器，不能用 A 机器路径或本机诊断结果冒充 B 机器事实。缺少另一台机器访问能力时交付该端可直接复制的交接步骤，不假装已完成。

1. 探测本机 OS/架构、运行用户、AgentNotify 实际版本与数据目录、受支持客户端及准确版本。核对用户提供的 AgentNotify 程序包、START_HERE.md、MIGRATION.md、当前 CLI 帮助和配置 schema。使用已验证来源的对应平台程序包，不把源码当已安装产品；Windows 包不能用于 macOS/Linux，后两者原生实测待办必须保留。
2. 源机器只整理经用户允许携带的通知偏好：通知模式与空闲秒数、提问/回答正文开关、免打扰时段/行为/时区、留存天数、事件规则和观察阈值。只转交当前 schema 接受的字段，标注原时区；检查目标平台能力，缺失的观察/离席能力保持关闭并说明差异。邮箱与 SMTP 非秘密参数由用户选择在目标机重填或单独私密交接，不放入诊断包、聊天或公开仓库。
3. 不复制整个数据目录或 host.json；不搬运授权码、OAuth 令牌、系统凭据条目/引用、正文加密密钥、通知数据库/待发队列/历史正文、安装记录、机器实例 ID、计划任务、绝对路径、客户端 Hook 文件或信任记录。当前无专用跨机器导入导出命令，不编造命令；用目标端设置界面或经当前 schema 校验的非秘密配置变更完成偏好迁入，写前备份并比较版本，目标通知先保持关闭。
4. 在目标机器安装 AgentNotify，重新生成本机安装归属、系统凭据引用、正文密钥和客户端实例绑定；所有入口固定使用同一安全数据目录。由用户在目标机邮箱设置窗口输入授权码或完成官方 OAuth；只检查配置状态，不读取或传递秘密。正文开关依赖目标端真实可用的正文密钥，不能仅复制配置后宣称已准备好。
5. 新机器准备完成后，先在源机器关闭通知并停止其自有后台，确认停发；在途投递结果不确定时记录，不强杀、不搬队列、不自动补发。不能确认源机停发时，目标端继续关闭。客户端接入使用目标端真实路径及正式接口，先预演再仅合并 AgentNotify 自有条目，保留其他配置；首次信任由用户在客户端完成，不复制或伪造信任。
6. 确认源机已停发、目标后台健康、邮箱配置可用和客户端接入/信任状态后，按当前授权启用目标通知。回读偏好和状态，分别记录真实客户端事件、SMTP 接受和用户收件确认；本提示词不额外授权测试邮件。目标不可用时先关闭目标通知，再恢复源机器本次变更，避免两边同时发送；有并发编辑则停止覆盖并报告。

最后报告 A/B 两端实际完成项、保留与暂未支持的设置、安装/数据位置、客户端待信任动作和可恢复点。未访问的机器、未执行的迁移及未验证的收件明确列为待办。
