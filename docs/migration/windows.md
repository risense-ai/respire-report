# AgentNotify：迁移到新电脑

这里的迁移指将 AgentNotify 从 A 机器迁往 B 机器的新环境。当前交付的是单个 AgentNotify.exe、独立说明 ZIP 和 Agent 协助流程；尚无一键跨机器导出/导入功能。不要把运行目录整包复制当作迁移成功。

## 用户操作

1. 在 A 机器的“工具接入 → 迁移到新电脑”，或“诊断 → Agent 协助 → 迁移到新电脑”生成提示词。检查路径预览，再把提示词和脱敏包交给可访问本机的 Agent。
2. 将来源已确认的 AgentNotify.exe 和独立说明 ZIP带到 B 机器。诊断包只用于排查，不包含完整偏好或邮箱凭据；需要保留的设置由 Agent 按下方白名单整理，邮箱信息可在 B 机器重新填写。
3. 让 B 机器上的 Agent 按实际系统、客户端版本和本机路径安装配置。授权码只在 B 机器的邮箱设置窗口私密输入，不发到聊天。
4. 目标通知先保持关闭。准备就绪后，先停用 A 机器通知并确认后台停止，再完成 B 机器的客户端接入、用户信任与启用。不要同时让两台机器处理同一套通知来源。

## 可携带与必须重建的内容

| 内容 | 处理方式 |
| --- | --- |
| 通知模式、空闲秒数、正文开关、免打扰、事件规则、留存天数、观察阈值 | 按目标版本 config schema 逐字段核对；写入前备份和比较目标修订，不覆盖未知字段或并发编辑。目标先 disabled。 |
| 免打扰时区 | 明确保留固定时区还是跟随目标系统；不能把 A 机器时区默认为 B 机器事实。 |
| 邮箱地址、SMTP 主机/端口/加密方式 | 用户可在目标机重填，或明确允许后单独私密交接。不要放入可上传诊断包。 |
| 授权码、OAuth 令牌、系统凭据、正文密钥及其引用 | 不迁移。在目标机由软件重新建立引用与密钥，用户私密授权。 |
| host.json、安装记录、计划任务、实例 ID、绝对路径、客户端 Hook 和信任 | 不复制。在 B 机器探测并重新生成、预演、应用及审核。 |
| 通知数据库、历史正文、已发送记录与待发队列 | 不迁移，不重放历史邮件。在途结果不确定时保留说明，不自动补发。 |

配置文件不是独立可运行的备份。正文开关依赖目标机系统安全存储内的真实正文密钥；客户端结束通知依赖目标端正确的绑定和信任。不要仅复制 config.json 后声称全部就绪。

## Agent 执行顺序

先读独立说明包 START_HERE.md、当前 CLI 帮助及 config schema，确认操作端是 A 还是 B。已有明确迁移授权内直接完成必要且可逆的步骤，不要求用户手工改路径或 JSON；无另一台机器的访问能力时提供该端交接说明。

- 目标准备：探测 OS/架构、WebView2（Windows）、版本及数据目录；使用对应平台且来源已确认的程序包，安全安装本软件。所有入口、后台和客户端命令使用同一个目标数据目录。
- 偏好迁入：只处理上述可携带字段，目标通知先关闭；校验当前 schema、能力门槛和时区。不存在的导入/导出命令不得臆造，可通过设置界面或受控的 schema 校验配置变更完成。
- 私密输入：由用户在目标邮箱设置界面保存授权码；Agent 仅核对“已配置”状态，不读取、打印或复制秘密。
- 切换：源端关闭通知、停止自有后台并确认无在途发送；目标端使用真实客户端路径/版本预演接入，仅合并本软件条目，用户完成客户端信任后启用。
- 核验：配置回读、后台健康、真实客户端事件、SMTP 接受、用户实际收件分别报告。没有明确发送授权，不额外发测试邮件。
- 回退：先关闭目标通知，再恢复源端本次拥有且未被用户另改的设置；不得双开，不覆盖新编辑，不回放队列。

## 平台与支持边界

Windows 先验证。macOS/Linux 原生服务、安装和实机支持仍是待办，不能把 Windows 程序包复制过去后称可用。空闲/锁屏能力、任务观察能力须逐平台核对；缺可靠事件信号时观察保持关闭，阈值可保留。

若安全目录检查失败，选择经过校验的显式数据目录并让所有入口一致使用它；不放宽系统目录权限。重复安装应复用已确认归属的 AgentNotify 实例，不能另建一个相同来源的发送器。

若源机器启用了 Codex 只读备用接入，目标机器需重新核对本地版本、数据库/schema、实例绑定并完成初始化；不复制 observer 游标、数据库或机器绑定。目标首次基线排除当时已完成历史，跟踪当时进行中任务；不能用源机游标补发旧邮件。初始化成功后才为该实例切换完成通知来源，原有 Hook 生命周期仍保留；切源不等于完成客户端信任或收件验收。
