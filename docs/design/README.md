# AgentNotify 设计与实施计划包

日期：2026-10-30。工作名称：AgentNotify。

这是 AgentNotify 的产品设计资料；实际实现与运行能力以对应程序版本及验收记录为准。设计文档不授权安装、修改配置或发送测试邮件。迁移指本软件从 A 机器迁到 B 机器。

## 已确认方向

- Rust 原生通知核心，Tauri 2 + Vue 3 设置界面。
- 用户配置邮箱、授权方式、收件邮箱和通知偏好；程序自动处理常见接入。
- 程序不能自动完成时，提供无需手填占位符的一键 Agent 提示词和脱敏材料，由用户选用的 Agent 接管。
- 首版本机 Windows、macOS、Linux；Windows 先实测，macOS/Linux实机验收保留待办。
- 远程服务器、WSL、容器和云端接收不在首版范围。
- Codex、Claude Code作为首批明确事件接口目标；WorkBuddy保留独立适配待办，不冒充已经支持。

## 开发者接手

先完整阅读设计与计划，再选择计划内任务；公共类型以M1建立的Schema/生成代码为准，不在适配器或UI自创字段。产品实现必须另获执行任务授权，本资料本身不授予本机操作权限。

正式源码应置于独立 `AgentNotify/` 项目，实际目录在开始实施时确认；当前设计保存在既有通知器旁边，避免混进Java示例工程。本轮没有初始化仓库或创建源码目录。

文档中的CLI、包结构、状态值和界面均为规划，尚不可当成现成命令运行。若将提示词直接交给Agent而仅提供此设计包，预期行为是设计核查，不是假装完成安装。

## 进入实施前需要落实

正式源码位置与发布身份；所选邮箱服务商的开发者OAuth注册（若使用）；代码签名/发布渠道；可授权试发的测试邮箱。缺少某项时继续完成不依赖它的实现，明确阻塞其相应验收，不能假报全功能完成。

完成软件开发以后，用户安装场景应只剩邮箱私密输入、通知偏好，以及客户端/操作系统不可代替的确认；不要求用户自行拼路径或修改JSON。Agent协助是已知自动化能力之外的补充，不能把没有正式接口的客户端包装成已支持。
