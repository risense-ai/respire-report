# Codex 只读备用接入实施计划

> 用户已授权优先恢复正常任务通知。按当前明确分工实施，不重新审批、不递归分派。

**目标：** 在宿主 Hook 触发不可靠的当前环境，为已明确启用的 Codex 实例增加本地只读完成观察通道；不修改 Codex 数据，不补发已完成历史。

**架构：** Codex adapter 读取 `thread_history_1.sqlite` 和 `state_5.sqlite` 元数据，后台每 2 秒扫描，核心仍只接收中立事件。版本、数据库与 schema 兼容必须被实际验证，失配报告 degraded。此方案不是所有 Codex 版本通用的正式事件 API。

## 固定契约

- 首次成功初始化建立基线，排除已完成历史，跟踪基线时仍进行中的任务。持久游标只在接收确认后推进，重试使用稳定入站 ID 恢复去重。
- 只对启用 observer 的具体实例仲裁完成来源；初始化成功才切换。切换后 observer 独占完成类通知，原已信任 Hook 命令不改，生命周期保留。不宣称任意 Hook/observer 双源事件 ID 已统一，尤其不能假定子代理跨源映射可证实。
- 普通 `thread_spawn` 子代理保留；根据结构化来源排除 guardian。未知来源不按 JSON 正文形状推断后台，不误删普通 JSON 回答。
- 问答只按用户开关、针对新匹配轮次有界读取；不能把上一轮正文附到新任务，缺正文不编造。凭据、全文转录和用户内容不进入诊断。
- 数据库只读，锁忙/版本或 schema 失配需可诊断；降级不得伪装健康或自动重放历史。不为恢复通知修改客户端数据库、Hook 信任或重启客户端。

## 首次启用与故障边界

首次启用要求具体实例无既有 Hook 入站记录，且 AgentNotify 整个 spool 为空；有 Hook 历史的实例暂不支持在线切换，明确拒绝，不清除数据绕过，也不猜测跨通道 child ID 去重。本机零 ingress 是实施时需再核对的前置条件，不是通用假设。首次 baseline 与启用通过共享仲裁锁阻止 Hook 并发入队。已启用 observer 重启保持来源，不重新补历史；故障降级而不自动回退 Hook 完成通知。

native 确认启用接口为 `AgentNotify.exe --data-dir <root> observer enable codex --instance-id <已登记UUID>`；当前绑定版本只支持 `0.166.0-alpha.5.1`，不按线程创建版本排除续轮。最多扫描 10 万条 turn 元数据，超限 degraded；每批最多 32 新事件。正文有界按同 session/turn 匹配，缺失为空。

- [ ] native：执行必要构建与最小针对性检查，回报准确产物摘要；受控本机配置/更新由其负责。
- [x] 文档：更新公开使用/Agent协助/迁移和验收边界，不使用内部协作角色名，不提供未经实现确认的启用命令。
- [x] 包装：收到最终构建后仅 `scripts/package.ps1 -SkipBuild`；交付单 EXE 与独立说明 ZIP，核对摘要及包内容，不重复构建或运行。
- [ ] 独立验收：核对无历史补发、基线进行中任务、ACK/重启去重、实例仲裁、子代理/来源分类、正文匹配与兼容降级；实际未执行项保持待办。

## 验证与待办

当前原宿主自然 Hook 通知尚未证明恢复；既有 app-server 解析/信任与非法输入诊断不代表正常会话通知通过。备用接入实现、启用、观察到中立事件、SMTP 接受、用户收件分层记录，不用构建或单封测试邮件替代自然会话验证。macOS/Linux 和未知 Codex 版本不扩展宣称支持。测试范围遵循用户减少测试的要求，不新增大套件，不为文档自行发信或改本机配置。

兼容限制：不支持启用观察接入后从外部导入或替换 Codex 历史数据库；数据库时间精度为秒，无法可靠区分同秒导入的历史与新完成任务。正常实时任务按首次基线、当时进行中任务和新任务标识处理，不能为过滤导入历史而丢弃同秒完成任务。来源过滤目前只排除已证实的结构化 guardian 来源，尚不能精确识别全部 Respire 后台记忆来源；未知来源保留，避免误伤普通 JSON 回答和真实子代理。不承诺既有精准后台过滤已经完整覆盖观察接入。

同一 AgentNotify 数据目录中，同一个规范化 CODEX_HOME 只能登记一个 observer；程序通过全局启用锁和登记记录拒绝第二实例，不能为同一来源重复创建观察器。
