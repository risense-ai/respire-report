# Windows 桌面入口与托盘实施计划（2026-11-02）

本轮实施采用统一可见入口，内部保留 CLI、daemon、Tauri 三个职责；不做物理单 exe 重构，不改旧通知工具/Hook/秘密。减少测试，仅合并前端后做必要生产构建和独立静态验收。

1. Tauri启用本地缓存tray-icon，增加原生托盘菜单：打开设置、启用通知、免打扰、退出程序。菜单从真实配置读取，CAS保存并触发现有安全activate；失败保留窗口并显示固定诊断码。配置更改事件仅提醒前端刷新，不覆盖未保存草稿。
2. X关闭仅在托盘初始化成功时隐藏；初始化失败保留普通窗口。“退出程序”直接结束GUI和托盘，不读取或保存配置，不停止、启动或重载daemon；后台继续按现有设置通知。退出不受配置损坏或菜单开关忙状态阻塞，随后可由桌面快捷方式重新打开设置。停止通知使用独立的通知开关。
3. 保留现有daemon单实例；GUI单实例唤醒协议不在本轮范围，不新增文件IPC或网络端口。
4. desktop_info提供真实版本、数据根、运行诊断。GUI启动不自动启用通知、不读取旧凭据。生产CLI隐藏控制台，标准管道输出继续供Hook/脚本使用。
5. Windows提供Start.vbs可见唯一入口，经隐藏PowerShell查找现有安装后由稳定launcher打开正确root；检测profile和LocalAppData现有安装，若无安装默认使用profile。多处已安装时拒绝猜测。保留旧Start.cmd兼容重定向，安装/卸载维护入口不自动发送。
6. 前端由独立执行者负责；最终重新构建前端再构建Rust，生成开发包。安装替换及关闭用户旧窗口必须等待主控独立验收后授权。

关键限制：任务当前登录自启仍负责daemon；tray属于用户GUI，登录时自动拉起tray不在本轮偷偷增加。macOS/Linux实测待办。菜单退出仅关闭GUI和托盘，不干预后台及在途SMTP投递；通知继续遵守现有配置。

实际入口联调补充：首次配置已建数据目录但尚无安装记录时，仅在无安装文件、无发送者、无同名任务情况下报告未安装；其他缺失归属仍拒绝。任务路径允许完整绝对目录的等价斜杠/大小写表示，保留精确命令语法并拒绝父目录及设备命名空间。Windows命名管道以安全数据目录的实际规范路径和当前用户SID派生，避免同一目录不同写法无法通信。以上是本轮直接调用链修复，未改变旧工具或客户Hook。
