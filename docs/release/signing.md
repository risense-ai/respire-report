# 签名与安全维护边界

Windows 交付一个未签名开发版 `AgentNotify.exe`，说明 ZIP 单独提供。正式 Release 和自动更新保持关闭；缺少正式发布者信任根时不得放行。不使用临时开发密钥或“哈希即签名”的替代。OS Authenticode 与更新清单签名是独立门槛；macOS 签名/公证、Linux 分发待办。

`meta/RUNTIME-SHA256.txt` 是同次交付 EXE 的 SHA256，文件名指向另行下载的 AgentNotify.exe。`meta/SHA256SUMS.txt` 仅列说明 ZIP 内的文件，以说明解压根目录为基准。`meta/BUILD-INFO.json` 记录本次运行文件摘要与未签名状态。哈希可核对一致性，不能独立确认发布者身份。

## 单 EXE 与既有安装

新版本把 GUI、CLI 和后台链接到同一程序；不是自解压多程序安装器。安装仍需要受保护的数据目录、清单与当前用户任务。既有稳定 launcher 与回退版本属于兼容安装资源，不应手动删除或移动。单 EXE 交付不授权绕过安装所有权、二进制哈希或客户端信任检查。

需要维护时，先让 Agent 读取当前实际 CLI 帮助、安装记录与脱敏诊断，保存回退点；现有设置、系统凭据和 Hook 原始字节保持不变。不要使用历史三文件发布清单安装单 EXE，不把此前多 EXE 的 package_dir 或更新示例当作当前发布接口。单 EXE 安装会以 `unified_signed_update_pending` 拒绝旧三文件签名更新流程；正式签名更新尚未开放。需要升级时取得来源已确认的新版 AgentNotify.exe，由 Agent 在授权范围内核对当前版本与归属、保全现场和回退点，使用该版本实际支持的受控更新方式，保留设置及既有 Hook；先停止自有 GUI 与后台，再由外部新版 EXE 或 Agent 受控处理；不直接覆盖运行文件。当前没有内置静默替换正在运行自身的能力，不把此流程称为现成自动更新。

## 恢复边界

存在维护日志或队列快照时，按程序实际支持的恢复接口处理，不手删维护标记。恢复消费后不得回滚旧数据快照而丢弃新事件、投递和幂等记录；SMTP 投递结果不确定时不自动重发。后台恢复与是否启用通知需单独核对，不能由文件替换推断已正常收件。

构建、打包、静态审查分别记录；真实升级、自然客户端事件和邮件收件未验证时保留待办。
