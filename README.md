# Windows Python 初版通知工具（归档）

本分支 `archive/codex-notify-py` 保存 Windows Python 专用初版，仅供归档与迁移参考；它不是 AgentNotify 通用正式版，也不是正式 release。不支持 macOS 或 Linux，不包含个人配置、邮箱信息、授权码或运行数据。

# Codex 邮件通知

运行环境：Windows，Python 3.12 或以上（推荐 3.13）。

首次安装或换电脑：把本目录交给 Codex 等 agent，从 `START_HERE.md` 开始。`AGENTS.md` 是 agent 入口，`Codex邮件通知器使用与迁移说明.md` 是完整操作契约；`Install.ps1` 探测 Python，`install_notifier.py` 校验包、备份并合并 Hook。默认安装到当前用户的 `%LOCALAPPDATA%\CodexNotifier`，不要求固定盘符。包内仅有无个人信息的 `settings.example.json`。

设置入口：运行 `notifier.py settings`，或使用安装后的“通知设置”快捷方式。

## 通知范围

- `Stop`：一轮处理结束；
- `Interrupt`：用户主动中断当前轮次；
- `UserPromptSubmit`：只登记轮次开始，用于后续无进展检测，不发送邮件；
- `SessionEnd`：只关闭该会话的监测状态，不发送邮件；
- 不监听 `PermissionRequest`，自动批准等非阻断事件不会触发邮件。

Respire 后台记忆的标准成功回执（`stored`、`already-stored`、`nothing-to-store`、`read-only`），以及长对话分块提炼的标准 `facts/constraints` 输出不发邮件，记录为 `suppressed_respire`；后台提交不启动无进展监测，诊断状态为 `ignored_respire_background`。判定同时核对进程继承的 `PLUGIN_ROOT`、`PLUGIN_DATA` 与当前 Codex 目录及 Respire 插件清单，确认来源后才检查原始完整输出。普通会话、JSON 回答及正常子代理仍按原规则通知；中断、失败、未知结果和来源无法确认时也保留原通知规则。它不是后台归档状态的独立监控，静默不等于已核验记忆落库或提炼事实。

提炼输出按插件协议校验顶层字段、条目字段、状态、条数、UTF-16 长度及 `item-数字-part-数字` 来源格式；通知器无法核对来源是否属于原始分块，这不构成对提炼内容的独立验收。诊断 `background_filter` 只记录 `respire_source` 和 `output_kind`：`receipt` 为保存回执，`extraction` 为分块提炼，`unrecognized` 为来源已确认但格式未匹配，`not_checked` 为来源未确认；不保存正文或来源条目。

升级或换机需一并复制新版 `notifier.py`；过滤不需要修改用户 Hook 或 SMTP 设置。默认 Codex 目录为当前用户的 `.codex`，设置了 `CODEX_HOME` 时使用该目录。若插件路径、数据目录或回执协议发生变化，无法确认的事件保留通知，不扩大过滤范围。旧队列不会按 JSON 内容追溯清理。

无进展检测依据轮次转录文件的最后活动时间。每个会话只保留最新活动监测；新的 `UserPromptSubmit` 会淘汰该会话旧监测，任意 `Stop` 或 `Interrupt` 会关闭该会话全部活动监测。超过“疑似无进展秒数”且轮次仍未结束时，只发送一次“会话疑似无进展”。这是启发式提示，不能证明任务一定卡死；长时间运行且没有转录输出的单个工具也可能命中。

## 通知模式

- `off`：关闭；
- `always`：命中会话范围且未被免打扰等规则抑制的通知事件发送；
- `auto`：仅当事件发生时电脑已锁屏，或键鼠空闲达到阈值时发送。

会话 ID 留空表示全部会话；填写后只处理列出的会话。完成事件在用户仍在电脑前时立即标记为 `suppressed`，以后锁屏不会补发旧事件。无进展监测在用户仍在场时继续观察，离席后若该轮仍无活动才通知。

免打扰默认启用，按电脑本地时间判断，默认时段为 23:00–07:30，包含开始、不包含结束，支持跨午夜。免打扰优先于 `always`，期间的事件不补发；无进展监测若在免打扰期间达到阈值，也会结束为抑制状态。设置界面可调整开关及开始、结束时间；上述为代码默认值，实际以本机设置为准。

## 数据与隐私

- 可分别选择邮件是否包含最新回复正文、本轮提问；本轮提问开关默认开启，实际以本机设置为准；
- 准备发送的 `Stop` 事件可按开关临时写入最新回复正文；准备发送的 `Stop`、`Interrupt` 事件均可按开关临时写入本轮提问；`suppressed` 事件不保存这些正文；
- 发送成功、永久失败或转为抑制后，正文立即从 `events.db` 清除；
- 事件元数据按“事件记录保留天数”自动清理，默认 30 天；
- SMTP 授权码由 Windows DPAPI 保存在 `smtp.credential.xml`，绑定当前 Windows 用户；不要提交或共享该文件。

## 诊断与边界

邮件显示事件类别、项目名称、会话标题和时间，不显示会话 ID。发送错误使用不含凭据和正文的分类码记录，例如 `smtp_auth_failed:535` 或 `os_error:10060`。状态命令会显示事件数量、错误分类和活动监测数量；当前不输出免打扰配置和本轮提问开关，需在设置界面核对。未收到邮件时也应检查免打扰时段。

脚本不会批准、拒绝、继续或中断 Codex 操作。`Stop` 只表示一轮停止，不代表业务成功。SMTP 发送与本地状态更新不能形成事务，极端情况下仍可能重复发送一次。

用户级 `hooks.json` 修改后，需要在 `/hooks` 或当前版本对应界面审核、信任新的 Hook 定义，并按客户端实际情况重载；若必须重启，先取得用户同意。仅安装文件不代表触发链已验收。
